# Figma Check Workflow

Figma MCPを使ってデザインを参照し、実装済みコードとのUI差分を検出する。
実装前の確認・実装後のレビュー、どちらにも使える。

---

## Phase 1: 対象の特定

**Goal**: チェックするFigmaフレームと対応するコンポーネントを特定する

**Actions**:
1. `$ARGUMENTS` の内容を判定する
   - **FigmaフレームIDの場合**（数字のみ、例: `16:309`）: そのIDを直接使う
   - **タスク名・キーワードの場合**: `.claude/TASKS.md` を読み込み、該当タスクの `Figma フレーム id` を探す
   - **省略された場合**: TASKS.md の実装中タスクからFigmaフレームIDを持つものを列挙し、ユーザーに選ばせる

2. フレームIDが見つかった場合は対応するページ・コンポーネントも特定する
   - TASKS.md の `参照ファイル` や `実装メモ` からページパスを読み取る
   - 該当するコンポーネントファイルをリストアップする

---

## Phase 2: Figmaデザインの参照

**Goal**: Figmaフレームのデザイン仕様を読み取る

**Actions**:
1. Figma MCPで対象フレームを参照する
   ```
   mcp__figma__view_node(fileKey: <プロジェクトのFigmaファイルキー>, nodeId: "<フレームID>")
   ```
2. 取得した情報から以下を読み取る
   - **レイアウト**: 要素の配置・余白・サイズ感
   - **テキスト**: ラベル・フォントサイズ・文言
   - **色**: 背景・テキスト・ボタン・アイコンの色
   - **状態**: 通常・ホバー・選択中・エラー・空状態 などの状態ごとのデザイン
   - **インタラクション**: タップ/クリック時の遷移先やアニメーション

3. Figmaファイルキーが不明な場合はユーザーに確認する

---

## Phase 3: 実装の確認

**Goal**: 対応するコードの現在の実装状態を把握する

**Actions**:
1. Phase 1 で特定したコンポーネントファイルを読み込む
2. 対応するCSSファイル（`.module.css`）も読み込む
3. 実装済みの要素・スタイルをリストアップする
4. 実際の表示を確認できる場合は `npm run dev` で起動して目視確認する

---

## Phase 4: 差分の検出と報告

**Goal**: デザインと実装の差分を種類別に整理して報告する

**差分の種類:**

| 種類 | 例 |
|------|-----|
| 未実装の要素 | デザインにあるボタン・テキストがコードにない |
| レイアウトのズレ | 余白・配置がデザインと異なる |
| テキストの違い | ラベル文言がデザインと一致しない |
| 色のズレ | ボタン色・背景色がデザインと異なる |
| 状態の未実装 | エラー状態・空状態のデザインが未実装 |
| 遷移の違い | タップ後の遷移先がデザインと異なる |

**報告フォーマット:**
```
【未実装】商品カードの「いいねボタン」
  Figma: ハートアイコン + いいね数 が右上に固定表示
  実装:  該当する要素なし
  対応:  merchandises/[id]/page.tsx にアイコンを追加

【ズレあり】購入ボタンの色
  Figma: #0B3D2E（ダークグリーン）
  実装:  #000000（黒）
  対応:  page.module.css の .buyButton を修正

【確認不要】ヘッダータイトル
  Figma: 「商品詳細」
  実装:  「商品詳細」（一致）
```

**Actions**:
1. 差分を上記フォーマットで列挙する
2. 「対応不要（意図的な変更）」と「修正すべき差分」を分けてユーザーに確認する

---

## Phase 5: 修正の実施（オプション）

**Goal**: ユーザーが修正を希望した差分をコードに反映する

**Actions**:
1. 修正対象をユーザーと合意する
2. 小さな差分（色・テキスト・余白）はその場で修正する
3. 大きな差分（未実装要素の追加）は `/coding <タスク名>` に引き渡す
4. 修正後は `npm run dev` で再確認する

---

## Phase 6: 完了報告

**Goal**: チェック結果を簡潔に伝える

**Actions**:
1. 検出した差分の数と種類を報告する（例: 「3件の差分を検出: 未実装1件・ズレ2件」）
2. 修正した内容を報告する
3. 残課題があれば TASKS.md への追記を提案する
