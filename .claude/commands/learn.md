# Learn: 実装理解の補完

Claudeが実装した内容を振り返り、ユーザーが理解できていない部分に対して学習コンテンツを自動生成する。

**出力先**: `../claude-learning/[ジャンル]/[トピック名]/`

ジャンル一覧:
| フォルダ名 | 対象 |
|---|---|
| `algorithm` | アルゴリズム・データ構造 |
| `database` | ORM・SQL・テーブル設計・マイグレーション |
| `language` | 言語構文・型システム（TS generics, async/await など） |
| `framework` | フレームワーク固有機能（Next.js App Router, React hooks など） |
| `library` | 個別ライブラリ（Zod, Stripe, date-fns など） |
| `architecture` | 設計パターン（DDD, MVC, SOLID, Clean Architecture など） |

---

## Phase 0: 起動確認

**Goal**: 学習セッションを始めるか確認する

**Actions**:
1. ユーザーに一言聞く:
   ```
   今回の実装で「なんとなく動いているけど仕組みがわからない」部分はありますか？
   あれば学習コンテンツを生成します。（スキップする場合は「なし」と答えてください）
   ```
2. 「なし」「スキップ」「いいえ」などの場合は即終了する
3. それ以外の場合は Phase 1 に進む

---

## Phase 1: 実装内容の把握

**Goal**: 今回Claudeが実装した内容を特定する

**Actions**:
1. `$ARGUMENTS` があれば対象ブランチ/コミットとして使う
2. なければ現在のブランチの直近コミットを確認する
   ```bash
   git log --oneline -10
   git diff HEAD~1..HEAD --name-only
   ```
3. 変更されたファイルを実際に読んで実装パターン・使われた技術を把握する

---

## Phase 2: 学習トピックの抽出

**Goal**: 理解度チェックの対象トピックをリストアップする

**Actions**:
1. 実装内容から以下の観点で学習候補を検出する:
   - 新しく使われたライブラリ・API・Hook
   - 非自明なロジック・アルゴリズム
   - 設計パターン（状態管理・非同期処理・Context・カスタムHooks など）
   - 複雑な型定義・ジェネリクス
   - DB操作・クエリ・トランザクション
   - 認証・セキュリティ周り
2. 候補を重要度順に最大5件に絞る
3. 各トピックについて「ジャンル」「トピック名（英語ケバブケース）」「1〜2文のやさしい説明」を用意する

---

## Phase 3: インタビュー（理解度チェック）

**Goal**: ユーザーが理解できていない部分を特定する

**Rules**:
- トピックを **1つずつ** 提示し、ユーザーの回答を待ってから次に進む
- 回答の受け付け: 「はい（理解した）」「いいえ（わからない）」「なんとなく（ふんわり）」
- 「いいえ」「なんとなく」は学習コンテンツ生成対象に追加する
- 全トピックが「はい」なら Phase 4 をスキップして終了する

**質問フォーマット**:
```
📌 トピック X/Y: [トピック名]（[ジャンル]）

[実装コードの該当箇所を1ブロック引用]

[1〜2文のやさしい説明]

理解できていますか？（はい / いいえ / なんとなく）
```

---

## Phase 4: 学習コンテンツ生成

**Goal**: 理解不足のトピックごとに4種類の学習ファイルを生成する

**出力先**: `../claude-learning/[ジャンル]/[トピック名]/`

各トピックについて以下の4ファイルを作成する。

---

### 1. `README.md` ── 概念説明

```markdown
# [トピック名]

> ジャンル: [ジャンル] | 生成日: [YYYY-MM-DD]

## なぜ使うのか
[動機・解決したい問題を2〜3文で]

## どう動くのか
[仕組みの説明。図（ASCII）があれば添える]

## このプロジェクトでの使われ方
[実際のコードを引用して解説]

## まとめ
> [トピック名]とは: [一文の定義]
```

---

### 2. `handson/STEPS.md` ── ステップ別ハンズオン

```markdown
# ハンズオン: [トピック名]を自分で書く

## 目標
[このハンズオンを終えると何ができるようになるか]

## Step 1: [最小の出発点]
**やること**: ...
**コード（穴埋め）**:
\`\`\`ts
// TODO: ここを実装してください
\`\`\`
**なぜそう書くか**: ...

<details>
<summary>完成コード</summary>

\`\`\`ts
// 答え
\`\`\`
</details>

## Step 2: ...
（繰り返し、3〜5ステップ）

## 完走チェック
- [ ] [確認ポイント1]
- [ ] [確認ポイント2]
```

---

### 3. `mini-project/README.md` ── ミニプロジェクト

```markdown
# ミニプロジェクト: [テーマ]

> 目安: 30〜60分

## 課題
[学んだ概念を使う小さなアプリ・機能の説明]

## 要件
- [ ] 要件1
- [ ] 要件2
- [ ] 要件3

## ヒント
1. まず〜をする
2. 次に〜をする

## 完成例
[完成形のコードまたは期待される出力]
```

---

### 4. `cheatsheet.md` ── Q&Aチートシート

```markdown
# [トピック名] チートシート

## よくある疑問

**Q. [疑問1]**
A. [回答]
\`\`\`ts
// スニペット
\`\`\`

（5〜10問）

---

## 一行まとめ
> [トピック名]とは: [一文の定義]
```

---

## Phase 5: 完了報告

**Goal**: 生成したコンテンツを案内する

**Actions**:
1. 生成したフォルダ・ファイルの一覧をツリー形式で表示する:
   ```
   ../claude-learning/
   ├── [ジャンル1]/
   │   └── [トピック名]/
   │       ├── README.md
   │       ├── handson/STEPS.md
   │       ├── mini-project/README.md
   │       └── cheatsheet.md
   └── [ジャンル2]/
       └── ...
   ```
2. 推奨する学習順序を伝える:
   ```
   1. README.md で「なぜ・どう動くか」を掴む
   2. handson/STEPS.md を自分で写経する
   3. mini-project/ で応用する
   4. わからなくなったら cheatsheet.md を参照する
   ```
3. 「次のコーディング前に一度読み返すと定着しやすいです」と伝える
