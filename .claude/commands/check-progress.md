# Check Progress Workflow

各ブランチのコミット履歴を精査し、MDファイルに書かれた情報との乖離を検出・修正する。

---

## Phase 1: コミット履歴の収集

**Goal**: 全ブランチの変更内容を網羅的に把握する

**Actions**:
1. 全ブランチの一覧を取得する
   ```bash
   git branch -a
   ```
2. 全ブランチのコミット履歴を取得する（ブランチ・コミットメッセージ・ファイル変更）
   ```bash
   git log --all --oneline --decorate
   ```
3. 各ブランチの詳細なコミット内容を確認する（変更ファイル・差分）
   ```bash
   git log --all --stat --format="%H %D %s" | head -200
   ```
4. `$ARGUMENTS` でブランチ名が指定された場合はそのブランチのみを対象にする
5. 最新コミット（直近20件程度）の差分内容を読んで実装済みの機能を把握する
   ```bash
   git show <commit-hash> --stat
   ```

**Checklist (実装済みと判断する基準)**:
- コミットメッセージに "FEAT:", "feat:", "機能" などが含まれる
- 該当機能に関連するファイルが追加・変更されている
- マイグレーションファイルや新規コンポーネントが追加されている
- テーブル・ページ・APIルートが新規作成されている

---

## Phase 2: MDファイルの読み込み

**Goal**: プロジェクト内の全MDファイルの現在の記述を把握する

**Actions**:
1. 対象MDファイルをすべて読み込む（優先順位順）
   - `.claude/TASKS.md` — タスクのステータス管理
   - `PROGRESS.md` — 実装進捗・バグ一覧
   - `MISSING_FEATURES.md` — 未実装機能の一覧
   - `PRODUCT_OPERATIONS.md` — 機能仕様・ステータス遷移
   - `ARCHITECTURE.md` — アーキテクチャ概要
   - `FUNCTIONS.md` — 関数・コンポーネント一覧
2. `$ARGUMENTS` でMDファイル名が指定された場合はそのファイルのみを対象にする
3. 各MDファイルの「実装済み」「未実装」「進行中」に関する記述をリストアップする

---

## Phase 3: 差分の検出

**Goal**: コミット履歴とMDファイルの記述を突き合わせ、乖離を発見する

**検出する乖離の種類**:

| 種類 | 例 |
|------|-----|
| ステータスの古さ | TASKS.md で `[ ]` だが、コミットで実装済みと判断できる |
| 逆方向の乖離 | TASKS.md で `[x]` だが、ブランチが削除/リバートされている |
| ファイルパスの変更 | MDに書かれたパスが実際には移動・リネームされている |
| 機能仕様の変更 | コミット内容がMDの仕様説明と食い違っている |
| バグ修正済み | PROGRESS.md のバグ欄に残っているが、修正コミットが存在する |
| 未記載の実装 | コミットで実装されているがMDに一切記載がない機能 |
| ブランチ情報の誤り | TASKS.md のブランチ名が変更されている |

**Actions**:
1. Phase 1 で把握した実装済み機能と TASKS.md のステータスを突き合わせる
2. PROGRESS.md のバグ一覧と修正コミットを突き合わせる
3. MISSING_FEATURES.md に残っている項目で実装済みのものを探す
4. FUNCTIONS.md・ARCHITECTURE.md のパス・関数名が現在のコードと一致するか確認する
5. 乖離を以下のフォーマットでリストアップする

**出力フォーマット**:
```
[種類] ファイル名:セクション名
  現在の記述: "..."
  実際の状態: コミット <hash> で <内容>
  推奨修正: "..."
```

---

## Phase 4: 修正内容の提示と確認

**Goal**: 検出した乖離をユーザーに提示し、修正方針を確認する

**Actions**:
1. 検出した乖離を種類別・優先度別にまとめてユーザーに提示する
2. 修正が確実なもの（コミットから明らかに判断できるもの）と、要確認なもの（判断が難しいもの）を分けて提示する
3. ユーザーに「全部修正する」「選択して修正する」「確認だけ」のどれかを確認する
4. **ユーザーの承認なしに修正を開始しない**

---

## Phase 5: MDファイルの修正

**Goal**: 承認された乖離を修正し、MDファイルを最新状態に保つ

**Rules**:
- ステータス変更は証拠（コミットハッシュ）とともに行う
- `[ ]` → `[x]` に変更する場合は `**完了コミット**: <hash>` を追記する
- `[~]` (進行中) への変更は、現在作業中のブランチが存在する場合のみ
- 削除ではなく更新を優先する（削除するとコンテキストが失われる）
- FUNCTIONS.md・ARCHITECTURE.md のパス・関数名は実際のコードを `Read` して確認してから修正する

**Actions**:
1. 承認された乖離を上から順に修正する
2. 修正後は変更内容を簡潔に報告する

---

## Phase 6: 完了報告

**Goal**: 何を修正したかを簡潔に伝える

**Actions**:
1. 修正したMDファイルと変更箇所を箇条書きで報告する
2. 「要確認」として残した乖離（コミットから判断できなかったもの）をユーザーに伝える
3. 次回の `/check-progress` までにやっておくべきことがあれば提示する
